# 部署文档

## 1. 适用范围

本文档适用于当前仓库 `online-novel` 的 Docker 容器部署。

当前项目实际情况：

- 单体 Spring Boot 项目
- 使用 Java 21
- 使用 MySQL 8
- 使用 Redis
- 文件上传依赖阿里云 OSS
- 当前仓库内未发现独立前端工程
- 当前仓库内未提供现成的 `Dockerfile` 和 `docker-compose.yml`

说明：

- 本文档以 Docker Compose 作为主部署方案
- 文档中的 `Dockerfile`、`docker-compose.yml`、`.env` 需要你按本文内容新增到项目中
- 如果你还有单独的前端项目，需要另外部署前端

---

## 2. 部署目标

完成部署后，服务应满足：

- MySQL、Redis 通过容器启动并可正常连接
- Spring Boot 服务以容器方式启动
- 接口可通过 Nginx 反向代理访问
- 上传头像、封面时可正常访问阿里云 OSS

---

服务器至少需要安装：

- Docker
- Docker Compose 插件

检查命令：

## 4. 部署目录建议

建议在服务器上使用如下目录：

```text
/opt/online-novel/
├─ docker-compose.yml
├─ Dockerfile
├─ .dockerignore
├─ .env
├─ src/
├─ pom.xml
├─ mvnw
├─ .mvn/
└─ mysql/
   └─ init/
      └─ init.sql
```

说明：

- 推荐直接把整个项目上传到服务器
- `mysql/init/init.sql` 用于 MySQL 容器首次启动时自动建表

---

## 5. 容器化方案说明

本方案包含 3 个容器：

- `app`：Spring Boot 服务
- `mysql`：MySQL 8
- `redis`：Redis 7

容器之间通过 Docker 网络通信：

- MySQL 主机名使用 `mysql`
- Redis 主机名使用 `redis`

因此，应用配置中的数据库和 Redis 地址不能再写 `127.0.0.1`，而应该写容器服务名。

## 6. 准备数据库初始化脚本

在项目根目录创建目录：

```bash
mkdir -p mysql/init
```

然后将 [init.sql](F:/project/novelProject/online-novel/src/main/resources/sql/init.sql) 复制到：

```text
mysql/init/init.sql
```

说明：

- MySQL 容器首次启动时会自动执行 `/docker-entrypoint-initdb.d/` 下的 `.sql` 文件
- 当前脚本主要用于建表
- 当前仓库未发现默认管理员初始化数据

## 7. 新增 Dockerfile

在项目根目录新增 `Dockerfile`：

```dockerfile
FROM maven:3.9.9-eclipse-temurin-21 AS builder

WORKDIR /app
COPY pom.xml .
COPY .mvn .mvn
COPY mvnw .
COPY src src
RUN chmod +x mvnw && ./mvnw clean package -DskipTests

FROM eclipse-temurin:21-jre

WORKDIR /app
COPY --from=builder /app/target/online-novel-0.0.1-SNAPSHOT.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
```

说明：

- 第一阶段使用 Maven 镜像打包
- 第二阶段使用 JRE 运行
- 当前项目 jar 名称来自 [pom.xml](F:/project/novelProject/online-novel/pom.xml)

## 9. 新增应用生产配置

不建议直接使用仓库内默认的 [application.yml](F:/project/novelProject/online-novel/src/main/resources/application.yml)，因为其中是本地开发配置。

建议在项目中新增：

```text
src/main/resources/application-prod.yml
```

内容示例：

```yaml
spring:
  application:
    name: online-novel

  datasource:
    url: jdbc:mysql://mysql:3306/online-novel?useUnicode=true&characterEncoding=utf-8&useSSL=false&serverTimezone=Asia/Shanghai
    username: ${MYSQL_USER}
    password: ${MYSQL_PASSWORD}

  data:
    redis:
      host: redis
      port: 6379

  servlet:
    multipart:
      max-file-size: 10MB
      max-request-size: 10MB

novel:
  jwt:
    secret: ${NOVEL_JWT_SECRET}
    ttl: 7200000

mybatis-plus:
  mapper-locations: classpath*:/mapper/**/*.xml
  configuration:
    map-underscore-to-camel-case: true

aliyun:
  oss:
    endpoint: https://oss-cn-chengdu.aliyuncs.com
    bucket-name: online-novel
    url-prefix: https://online-novel.oss-cn-chengdu.aliyuncs.com
    access-key-id: ${ALIYUN_OSS_ACCESS_KEY_ID}
    access-key-secret: ${ALIYUN_OSS_ACCESS_KEY_SECRET}
```

说明：

- `mysql` 和 `redis` 使用的是容器服务名
- `MYSQL_USER`、`MYSQL_PASSWORD`、`NOVEL_JWT_SECRET`、OSS 密钥都通过环境变量注入

## 11. 新增 docker-compose.yml

在项目根目录新增 `docker-compose.yml`：

```yaml
services:
  mysql:
    image: mysql:8.4
    container_name: online-novel-mysql
    restart: always
    environment:
      MYSQL_DATABASE: ${MYSQL_DATABASE}
      MYSQL_USER: ${MYSQL_USER}
      MYSQL_PASSWORD: ${MYSQL_PASSWORD}
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}
    command:
      - --character-set-server=utf8mb4
      - --collation-server=utf8mb4_0900_ai_ci
      - --default-time-zone=+08:00
    ports:
      - "3306:3306"
    volumes:
      - mysql_data:/var/lib/mysql
      - ./mysql/init:/docker-entrypoint-initdb.d

  redis:
    image: redis:7.4
    container_name: online-novel-redis
    restart: always
    ports:
      - "6379:6379"
    volumes:
      - redis_data:/data

  app:
    build:
      context: .
      dockerfile: Dockerfile
    container_name: online-novel-app
    restart: always
    depends_on:
      - mysql
      - redis
    environment:
      SPRING_PROFILES_ACTIVE: prod
      MYSQL_USER: ${MYSQL_USER}
      MYSQL_PASSWORD: ${MYSQL_PASSWORD}
      NOVEL_JWT_SECRET: ${NOVEL_JWT_SECRET}
      ALIYUN_OSS_ACCESS_KEY_ID: ${ALIYUN_OSS_ACCESS_KEY_ID}
      ALIYUN_OSS_ACCESS_KEY_SECRET: ${ALIYUN_OSS_ACCESS_KEY_SECRET}
    ports:
      - "8080:8080"

volumes:
  mysql_data:
  redis_data:
```

说明：

- `app` 容器通过 `SPRING_PROFILES_ACTIVE=prod` 读取 `application-prod.yml`
- `depends_on` 只保证启动顺序，不保证 MySQL 已完全可用
- 如果首次启动时 `app` 因数据库未就绪而失败，Docker 会按 `restart: always` 自动重启

## 12. 启动服务

在项目根目录执行：

```bash
docker compose up -d --build
```

查看容器状态：

```bash
docker compose ps
```

查看日志：

```bash
docker compose logs -f app
docker compose logs -f mysql
docker compose logs -f redis
```

说明：

- 首次启动会先拉取镜像并构建 `app` 镜像
- 首次启动 MySQL 时会自动执行初始化 SQL

## 13. 重启与停止

重启：

```bash
docker compose restart
```

停止：

```bash
docker compose down
```

停止并删除数据卷：

```bash
docker compose down -v
```

注意：

- `docker compose down -v` 会删除 MySQL 和 Redis 数据
- 生产环境不要随便执行

## 15. Nginx 反向代理

建议使用 Nginx 对外暴露服务，不直接将 8080 端口开放到公网。

示例配置：

```nginx
server {
    listen 80;
    server_name your-domain.com;

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

说明：

- 当前后端接口路径统一以 `/api/` 开头
- 推荐前端和后端走同一个域名，通过 `/api` 转发
- 这样可以绕开大部分跨域问题

## 16. 跨域注意事项

当前项目跨域配置在 [CorsConfig.java](F:/project/novelProject/online-novel/src/main/java/com/fengling/config/CorsConfig.java) 中，只允许：

```text
http://127.0.0.1:3000
http://localhost:3000
```

这意味着：

- 本地开发前端可直接访问后端
- 线上前端如果使用独立域名，浏览器会触发跨域失败

建议方案：

1. 前后端同域部署，通过 Nginx 反代 `/api`
2. 如果必须分离域名，再修改后端跨域白名单

如果只是部署当前后端服务，优先采用第 1 种方案。

## 17. 服务检查

项目启动后，至少检查以下内容：

### 17.1 检查容器状态

```bash
docker compose ps
```

### 17.2 检查 app 日志

```bash
docker compose logs -f app
```

### 17.3 检查数据库连接

查看日志中是否出现以下异常：

- `Communications link failure`
- `Access denied for user`
- `Unknown database`

### 17.4 检查 Redis 连接

查看日志中是否出现：

- `RedisConnectionFailureException`

### 17.5 检查上传功能

调用上传头像或上传封面接口，确认：

- OSS 密钥生效
- 文件能够成功上传

## 18. 常见问题

### 18.1 `docker compose up` 失败

原因可能包括：

- Docker 未安装
- Docker Compose 插件未安装
- 当前用户无 Docker 权限

处理方式：

```bash
docker -v
docker compose version
```

### 18.2 app 容器启动失败

原因可能包括：

- `application-prod.yml` 未创建
- `.env` 中变量缺失
- Maven 打包失败
- 数据库尚未就绪

优先检查：

```bash
docker compose logs -f app
```

### 18.3 MySQL 初始化脚本没有执行

原因可能包括：

- `mysql_data` 卷已经存在
- 初始化 SQL 只会在 MySQL 首次创建数据目录时执行

处理方式：

```bash
docker compose down -v
docker compose up -d
```

注意：

- 该操作会删除已有数据库数据

### 18.4 上传接口失败

原因可能包括：

- 没有配置 OSS 环境变量
- OSS bucket 名称不正确
- AccessKey 无权限

优先检查：

- `ALIYUN_OSS_ACCESS_KEY_ID`
- `ALIYUN_OSS_ACCESS_KEY_SECRET`

### 18.5 前端请求跨域失败

原因：

- 当前后端只放行了本地开发地址

处理方式：

- 优先使用同域名 Nginx 反向代理
- 或修改跨域配置后重新构建部署

### 18.6 没有管理员账号

当前初始化脚本未体现默认管理员账号。

如果你需要后台管理功能，需自行准备管理员用户数据。

## 19. 发布流程建议

建议使用以下最小发布流程：

1. 把项目上传到服务器
2. 新增 `Dockerfile`、`.dockerignore`、`docker-compose.yml`、`.env`
3. 新增 `src/main/resources/application-prod.yml`
4. 准备 `mysql/init/init.sql`
5. 执行 `docker compose up -d --build`
6. 查看 `docker compose logs -f app`
7. 配置 Nginx 并验证接口访问

- 1 台 Linux 服务器
- Docker
